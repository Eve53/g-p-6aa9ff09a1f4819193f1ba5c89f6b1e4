# 心理咨询订单列表｜核心问题交互解决方案

## 1. 目标与设计原则

本方案回应经更正后的 UX Audit 中两个高优先级问题，并补充一个中优先级的页面交互优化方向：

1. 即将开始的咨询缺少时间进度、进入条件与异常反馈（高优先级）。
2. “审核中”没有等待预期、下一步与恢复路径（高优先级）。
3. 在“我的咨询室”内，订单卡片的状态和操作结构不够统一，扫描成本较高（中优先级）。

**更正：** 产品方确认截图对应“我的咨询室”选中页。原审计根据错误的选中态推断导航不匹配，现已撤销。本方案不再要求更改“全部咨询师 / 我的咨询室”的一级导航名称；应先修正设计稿中“我的咨询室”的选中态。

核心目标是让用户进入页面后，在 3 秒内回答：

- 我现在最需要处理什么？
- 下一场咨询什么时候开始，现在能否进入？
- 其他订单分别处于什么状态，我是否需要操作？

设计原则：任务优先、单卡单主操作、状态可解释、即时反馈、异常可恢复。涉及具体开放时间和审核时长的数字应由业务规则配置，以下时间只作为推荐默认值。

## 2. 页面整体交互模型

### 2.1 一级导航

保留现有“全部咨询师 / 我的咨询室”两个标签。本截图是“我的咨询室”内容，因此设计稿中应将**“我的咨询室”**的文字、字重和下划线统一为选中态，将“全部咨询师”呈现为未选中态。具体两个标签在线上的切换行为，需要通过原型或真机验证，不能从当前截图推断。

交互规则：

- 从已购订单或预约提醒进入时，直接定位到“我的咨询室”及对应订单；从小程序常规入口进入时，可恢复用户上次选择，首次进入优先展示“我的咨询室”。
- 点击标签后在 `100ms` 内显示选中反馈。
- 数据尚未返回时保留导航不动，仅列表区域显示卡片骨架屏，避免整页闪烁。
- 标签切换采用 `180ms ease-out` 的淡入，不做横向长距离滑动，避免让用户误以为是流程前后关系。

### 2.2 “我的咨询室”内部筛选（建议新增）

使用三个筛选项：

| 筛选 | 内容 | 默认规则 |
|---|---|---|
| **待办** | 即将开始、待预约、待补充资料、审核异常等需要关注的订单 | 默认选中；显示数量徽标 |
| **全部** | 除已取消/已完成外的所有进行中订单 | 按紧迫度排序 |
| **历史** | 已完成、已取消、已关闭 | 按最近更新时间倒序 |

这是可选的列表效率优化，而非纠正一级导航错误。若订单量通常很少，可以先不增加二级筛选，只保留待办置顶和清晰的历史入口；订单量较多时再使用上述筛选。详细状态仍应在卡片中呈现，筛选只围绕“是否需要我处理”。

### 2.3 列表排序

同一筛选内按以下优先级自动排序：

1. 咨询进行中。
2. 距开始 24 小时内的预约。
3. 需要用户补充资料或确认的信息。
4. 审核超时或其他异常。
5. 审核中且无需用户操作。
6. 已购买但尚未预约。

用户不需要自己计算哪个订单最紧迫。刷新后若卡片顺序发生变化，列表顶部显示轻提示“已按最新状态排序”，不使用突兀跳动。

### 2.4 统一卡片结构

每张卡使用固定信息顺序：

1. **状态标签**：图标 + 状态文字，不能只使用颜色。
2. **核心时间或等待预期**：例如“今天 15:30–16:10”“预计明天 18:00 前完成审核”。
3. **咨询师与方式**：头像、姓名、视频/语音/线下。
4. **状态说明**：告诉用户是否需要操作。
5. **一个主按钮**：随状态变化。
6. **次级入口**：套餐名称行及右箭头始终进入套餐详情页；合同、预约记录、预约下次等原有快捷入口保留在卡片内，不因“更多”而全部隐藏。

点击规则：

- 主按钮只执行当前主要任务。
- 点击套餐名称行或右箭头进入“套餐详情页”，不执行展开/收起；点击其他非按钮区域可进入“咨询详情”，但不得覆盖套餐行及快捷入口的独立热区。
- 如仍有低频操作，可由“更多”打开底部操作面板；合同、预约记录、预约下次等原有高频入口保持可见。
- 所有触控区域不小于 `44×44px`；按钮按下后 `100ms` 内给出压下态。

### 2.5 页面状态

| 页面状态 | 呈现与操作 |
|---|---|
| 首次加载 | 3 张结构一致的卡片骨架；导航保持可见 |
| 刷新 | 保留旧数据，在列表顶部显示细进度条；不清空页面 |
| 空状态：无待办 | “暂时没有需要处理的咨询” + “查看全部咨询” |
| 空状态：无订单 | “还没有咨询订单” + “寻找合适的咨询师” |
| 加载失败 | “暂时无法获取咨询状态” + “重新加载”；保留上次成功数据并标记更新时间 |
| 离线 | 顶部提示“网络未连接，显示的是 HH:mm 的状态” + “重试” |

## 3. 方案一：“我的咨询室”内的订单状态与操作优化

### 3.1 用户流程

```text
进入“心理咨询”
  → 进入已选中的“我的咨询室”
  → 若启用二级筛选，默认呈现“待办”
  → 系统按紧迫度排序
  → 用户识别第一张卡的状态和主操作
      ├─ 有即将开始的咨询 → 进入咨询流程
      ├─ 有资料待补充 → 补充资料流程
      ├─ 有待预约套餐 → 预约时间流程
      └─ 无待办 → 查看全部或找咨询师
```

### 3.2 交互文案

| 场景 | 状态标签 | 状态说明 | 主按钮 |
|---|---|---|---|
| 近期预约 | 即将开始 | 距开始 28 分钟 | 检测设备 / 进入咨询室 |
| 进行中 | 咨询进行中 | 已开始 6 分钟 | 继续咨询 |
| 无预约 | 待预约 | 套餐剩余 8 次，请预约下次咨询 | 预约时间 |
| 审核中 | 审核中 | 预计明天 18:00 前完成，无需操作 | 查看进度 |
| 待补资料 | 需要补充资料 | 请在 9 月 18 日前补充信息 | 补充资料 |
| 已通过 | 审核已通过 | 现在可以选择咨询时间 | 预约时间 |
| 审核未通过 | 申请需调整 | 查看原因并修改申请 | 查看并修改 |

### 3.3 反馈规则

- 切换筛选：标签立即选中；超过 `300ms` 才返回数据时显示列表骨架或局部进度。
- 下拉刷新：旧卡片不消失；刷新完成显示“已更新”，`1.5s` 后淡出。
- 点击卡片：卡片按下态 `100–150ms`，随后进入详情；返回时恢复筛选和滚动位置。
- 状态在浏览中发生变化：在原卡片位置用 `200ms ease-in-out` 更新标签与按钮，并通过一行状态说明解释变化，不只变颜色。

### 3.4 验收标准

- 首次用户无需进入详情即可判断每张订单是否需要自己处理；“我的咨询室”的选中态在文字和下划线上保持一致。
- 任一卡片最多只有一个高视觉权重主按钮。
- 历史订单最多两次点击可达，不需要滚至列表底部。
- 切换筛选、进入详情再返回后，筛选和滚动位置被保留。
- 所有状态均使用文字；颜色不是唯一的信息载体。

## 4. 方案二：即将开始与进入咨询室

### 4.1 推荐时间状态机

开放时间应由业务配置；建议默认在开始前 15 分钟开放咨询室，开始前 30 分钟开放设备检测。

| 状态 | 触发条件 | 卡片反馈 | 主按钮行为 |
|---|---|---|---|
| 已预约 | 距开始 >30 分钟 | “今天 15:30 开始” + “距开始 2 小时” | 查看预约 |
| 准备期 | T-30 至 T-15 | “建议提前检测摄像头和麦克风” | 检测设备 |
| 可进入 | T-15 至开始 | “咨询室已开放 · 距开始 12 分钟” | 进入咨询室 |
| 进行中 | 开始至结束 | “咨询进行中 · 已开始 6 分钟” | 继续咨询 |
| 咨询师准备中 | 已到开放时间但房间未就绪 | “咨询师正在准备，页面将自动刷新” | 刷新状态 / 联系客服 |
| 已结束 | 结束后 | “本次咨询已结束” | 查看咨询记录 |
| 用户迟到 | 开始后且仍允许进入 | “咨询已开始 8 分钟，仍可进入” | 立即进入 |
| 无法进入 | 房间或权限异常 | 明确错误原因 | 重试 / 检查设置 / 联系客服 |

### 4.2 主流程

```text
用户打开“我的咨询室”的待办列表
  → 即将开始卡片自动置顶
  → 系统展示相对时间与开放状态
  → 用户点击“进入咨询室”
  → 按钮立即变为“正在进入…”并阻止重复点击
  → 检查网络、摄像头、麦克风和房间状态
      ├─ 全部正常 → 进入等候室/咨询室
      ├─ 权限未开 → 微信授权说明 → 重试检查
      ├─ 网络较差 → 提示切换网络，可继续尝试
      ├─ 房间未就绪 → 留在状态页并自动轮询
      └─ 服务异常 → 保留预约信息，提供重试与客服
```

### 4.3 进入按钮状态

| 状态 | 视觉与文案 | 交互 |
|---|---|---|
| 默认可用 | 实心主按钮“进入咨询室” | 点击触发检查 |
| 按下 | 轻微缩放至 98%，`100ms ease-out` | 确认已收到点击 |
| 加载 | 进度图标 + “正在进入…” | 禁止重复点击；保留按钮宽度 |
| 未到开放时间 | 次级按钮“查看预约”或“检测设备” | 不建议只放无解释的灰色禁用按钮 |
| 权限缺失 | 警示图标 + “开启权限后进入” | 打开权限说明 |
| 失败 | 错误图标 + “进入失败，重新尝试” | 允许重试，错误详情放在按钮下方 |
| 成功 | 对勾 + “正在打开咨询室” | `300ms` 内进入下一页 |

### 4.4 设备检测

建议使用独立轻量页面或底部面板，不要在点击主按钮后突然要求多项授权。

检查项：

- 网络：良好 / 较弱 / 未连接。
- 摄像头：已开启 / 未授权 / 未检测到。
- 麦克风：已开启 / 未授权 / 未检测到。
- 扬声器：提供 3 秒试听，可由用户主动触发。

状态文案遵循“发生了什么 + 原因 + 如何处理”：

- “无法使用麦克风。微信尚未获得麦克风权限，请前往设置开启后重试。”
- “当前网络不稳定，可能影响视频质量。建议切换 Wi‑Fi，也可以继续进入。”

检测结果应在本次预约期间记住，除非设备或权限发生变化。

### 4.5 咨询师未就绪

到达开放时间但房间未就绪时，不能让用户不断点击同一个入口：

- 显示：“咨询师正在准备，通常会在开始前开放。”
- 每 `10–15s` 自动刷新一次状态，并显示“上次检查：15:28:40”。
- 到预约开始时间仍未开放，提示升级为：“咨询师暂未进入，我们正在为你确认。”
- 提供“联系咨询助理”，并明确不会因此扣除咨询次数。该承诺需与真实业务规则一致，否则不要展示。
- 房间开放后，用系统通知或页面内明显状态变化提醒，并把按钮更新为“进入咨询室”。

### 4.6 提醒策略

在用户授权的前提下建议发送：

- T-24 小时：确认时间与改期截止时间。
- T-30 分钟：提醒检测设备。
- T-15 分钟：咨询室已开放，可进入。
- T+5 分钟且未进入：温和提醒“咨询已开始 5 分钟，仍可进入”。

页面内需展示通知授权状态，不重复强迫授权；拒绝后仍保留页面内提醒。

### 4.7 验收标准

- 用户在列表上即可看见距离开始时间和当前可执行动作。
- 点击进入后 `100ms` 内出现反馈，重复点击不会发起多个请求。
- 所有失败状态都有原因、恢复动作和返回路径，不出现只有“失败”的提示。
- 权限被拒绝后，用户可以从当前上下文完成设置并回来重试。
- 进入流程失败不会改变或丢失预约状态。

## 5. 方案三：“审核中”的可预期流程

### 5.1 审核状态模型

“审核中”不是单一状态，应拆为用户可理解的阶段，但不暴露内部术语：

| 用户状态 | 用户是否需要行动 | 卡片信息 | 主按钮 |
|---|---|---|---|
| 已提交 | 否 | “申请已提交 · 9月16日 10:20” | 查看进度 |
| 审核中 | 否 | “预计明天 18:00 前完成” | 查看进度 |
| 需要补充资料 | 是 | “请在 9月18日前补充，审核将暂停等待” | 补充资料 |
| 审核通过 | 是 | “申请已通过，请选择咨询时间” | 预约时间 |
| 申请需调整 | 是 | “部分信息需要修改，原申请已保留” | 查看并修改 |
| 审核超时 | 可选 | “审核比预计时间更久，我们正在确认” | 联系咨询助理 |
| 系统异常 | 可选 | “暂时无法获取最新进度，申请不会丢失” | 重新加载 |

### 5.2 卡片呈现

审核卡片必须同时给出四类信息：

1. 当前阶段：审核中。
2. 预计时间：预计明天 18:00 前完成。
3. 用户责任：暂时无需操作 / 需要补充资料。
4. 结果通知：完成后通过微信服务通知和页面消息告知。

推荐卡片文案：

```text
[审核中]
申请时间：1月30日 15:30–16:10
预计明天 18:00 前完成
暂时无需操作，结果将通过服务通知告知
[查看进度]
```

### 5.3 进度详情页

点击“查看进度”进入详情页，而非含义宽泛的“查看详情”。

页面结构：

- 顶部：当前结论和用户下一步。
- 中部：最多 4 个阶段的纵向时间线——已提交 → 审核中 → 审核完成 → 预约咨询。
- 当前节点：突出显示，显示更新时间和预计完成时间。
- 下方：申请的咨询师、时间、套餐摘要。
- 底部：与当前状态匹配的唯一主按钮。
- 次级入口：常见问题、联系咨询助理。

返回列表时，应将最新状态同步回原卡片，并保持用户的滚动位置。

### 5.4 状态变化反馈

| 变化 | 反馈方式 |
|---|---|
| 审核完成 | 微信服务通知 + 页面消息红点；卡片移动到待办顶部 |
| 需要补充资料 | 明确截止时间；卡片标记“需要你处理” |
| 提交补充资料 | 按钮立即变为“提交中…”；成功后显示“已提交，继续审核” |
| 预计时间延长 | 更新预计时间并解释原因，不能悄悄改时间 |
| 审核超时 | 自动进入“审核延迟”状态，提供咨询助理入口 |
| 获取状态失败 | 显示上次更新时间；不把失败误呈现为仍在审核 |

长时审核应采用后台处理：用户不需要停留等待。所有进度都应持久化，退出小程序后再次进入仍能恢复。

### 5.5 补充资料流程

```text
卡片提示“需要补充资料”
  → 点击“补充资料”
  → 展示缺失项与原因
  → 用户填写/上传
  → 提交前检查
  → 按钮变为“正在提交…”
      ├─ 成功 → “资料已提交，预计明天 18:00 前完成审核”
      ├─ 网络失败 → 保留全部内容 + “重新提交”
      └─ 文件失败 → 对应文件旁说明原因 + 重新上传
```

不应在提交失败后清空内容。若用户中途退出，应自动保存草稿并在返回时恢复。

### 5.6 审核失败或需调整

避免使用单独的“审核失败”结束流程。反馈必须包括：

- 什么未通过：使用用户语言描述具体项。
- 为什么：如规则允许，给出简短原因。
- 能做什么：修改并重新提交、改约其他时间、联系咨询助理。
- 什么会保留：明确套餐次数、付款和原申请资料是否受影响。

示例：

```text
申请时间需要调整
咨询师在 1月30日 15:30 暂时无法接待。你的套餐次数不会扣除。
[重新选择时间]  [联系咨询助理]
```

### 5.7 验收标准

- 任意审核状态都明确显示“是否需要用户操作”。
- 有可计算 SLA 时必须展示预计完成时间；发生延期时说明新的预期。
- 审核超过 10 秒的处理不阻塞用户，支持退出并通过通知获知结果。
- 补充资料提交失败后，文本和文件选择均不会丢失。
- 拒绝或调整结果必须提供至少一个可执行恢复路径，不能形成死路。

## 6. 跨方案交互标准

### 6.1 响应时间

| 用时 | 反馈 |
|---|---|
| `≤100ms` | 按钮按下、标签选中等视觉反馈 |
| `100ms–1s` | 按钮局部加载或列表骨架 |
| `1s–10s` | 明确正在做什么；可计算时显示进度 |
| `>10s` | 转为后台处理，允许离开并在完成后通知 |

### 6.2 动效

- 按钮和标签反馈：`100–150ms ease-out`。
- 卡片状态或位置调整：`200–250ms ease-in-out`。
- 底部面板：`250ms ease-out` 进入、`200ms ease-in` 退出。
- 文字数字变化不使用逐字动画；不得因动画延迟进入咨询。
- 系统启用减少动态效果时，使用即时替换或淡入，不使用缩放和位移动画。

### 6.3 可访问性与微信小程序适配

- 所有可点击目标最小 `44×44px`，相邻入口保留足够间距。
- 状态必须使用图标或形状 + 文字，不能只依赖蓝色、橙色或灰色。
- 普通文本对比度目标 `4.5:1`，大号文本和 UI 图形目标 `3:1`。
- 对微信读屏暴露按钮名称、当前状态和列表顺序；动态图文更新应有可感知文字变化。
- 微信返回键关闭当前底部面板或返回上一层，并保留页面筛选、滚动和草稿状态。
- 通知、摄像头和麦克风权限均采用按需请求：在用户触发相关动作后解释用途，再发起系统授权。

## 7. 建议原型覆盖的关键场景

第一轮可用性测试至少覆盖以下 8 条任务：

1. 首次进入，找到下一场咨询并说出当前能做什么。
2. 距开始 20 分钟，完成设备检测。
3. 距开始 10 分钟，进入咨询室。
4. 麦克风权限被拒绝后完成恢复。
5. 到点后咨询师尚未就绪，理解当前状态并找到帮助。
6. 找到一笔审核中的申请，并说出预计完成时间和是否需要操作。
7. 收到补充资料要求，填写后遇到网络错误并成功重试。
8. 查看已完成或已取消的历史订单后返回，页面位置不丢失。

核心衡量指标：首个正确点击率、完成时间、误入详情次数、重复点击次数、状态理解正确率、异常恢复成功率，以及咨询开始后 5 分钟仍未进入的比例。
