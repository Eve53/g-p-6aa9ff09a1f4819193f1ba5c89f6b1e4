# 预约列表改版后的交互解决方案 V2

## 0. 范围与不可改变项

本方案依据同目录的最新版 `report.md`，只解决 F-01 至 F-05。目标是：用户能快速识别每笔订单的状态，临近咨询时迅速进入咨询室，同时保留原有套餐管理能力。

**必须保留：**

- 一级导航“全部咨询师 / 我的咨询室”；当前页面选中“我的咨询室”。
- 新版的“距离开始”信息和清晰的可进入状态。
- 原版套餐模块中的剩余次数、进度条、按订单状态适用的合同/预约记录/预约下次入口。
- 套餐名称行及右箭头点击后进入**套餐详情页**；该行不是展开/收起控件。
- 原有的咨询师头像、姓名、咨询方式、咨询室入口与订单详情跳转。

**本轮明确不改：** 客服悬浮按钮位置、页面底部历史记录入口、一级导航名称和结构；不新增二级筛选、整页新布局、装饰性动效或新业务流程。

**证据边界：** 静态截图不能证明现有点击反馈、真实进入规则、审核时限、通知渠道或跳转是否已实现。以下行为规范是设计目标；落代码前需先检查现有实现，不覆盖真实业务规则。

## 1. 总体信息层级

每张卡只在列表层回答四件事：

1. **这是什么订单？** 咨询师、咨询方式；审核卡另显示申请的咨询时段。
2. **现在是什么状态？** 一处明确的状态标签，不重复出现同义标签和标题。
3. **现在该做什么？** 一个按紧迫度设置视觉权重的当前动作。
4. **套餐还剩多少、还能去哪？** 套餐名、剩余次数、进度条和原有快捷入口始终可见（仅适用于套餐订单）。

视觉权重顺序：**可进入的当前咨询 > 订单状态/申请时段 > 适用动作 > 套餐信息与快捷入口 > 规则解释**。规则解释在确有需要时才出现，不常驻每张卡。

### 卡片骨架（维持现有风格，仅调整内容密度）

| 区域 | 可进入预约 | 暂无预约 | 审核中 |
|---|---|---|---|
| 顶部 | “可进入”状态标签 + 咨询日期时间 | “暂无预约”作为唯一状态标题 | “审核中”状态标签 + **申请咨询日期时间** |
| 人物 | 头像、姓名、视频/语音等方式 | 同左 | 同左 |
| 一行补充信息 | “距开始 11 分钟”，不再重复“可进入” | 可省略；剩余次数放套餐区 | “预计审核完成：…”或“目前无需操作”，按数据可靠性呈现 |
| 当前动作 | 醒目的“进入咨询室” | 次级“立即预约” | “查看进度”，沿用现有跳转，不额外放大 |
| 底部 | 套餐名称行、剩余次数、进度条、合同/预约记录/预约下次等适用入口 | 同左，按该状态显示原有入口 | 保留“单次情绪疏导”及原有合同、预约记录等适用入口；无套餐则不伪造套餐进度 |

## 2. F-01：恢复套餐进度与快捷入口

### 展示规则

- 套餐名称、右箭头、剩余 `N/总次数` 保留在同一行。
- 恢复原版细进度条；当前截图中的“剩余 2/10”应对应约 20% 的剩余额度，不能将已使用比例误画成剩余比例。具体比例必须从真实剩余/总次数计算，零次、满额、数据缺失分别处理。
- 进度条下方恢复当前卡原有的快捷入口及顺序，不因新版“一卡一个主 CTA”而折叠或删除：
  - 已预约套餐卡：按现有业务展示“合同签署/查看合同”“预约记录”“预约下次”。
  - 暂无预约套餐卡：按现有业务展示“合同签署/查看合同”“预约记录”。
  - 单次咨询审核卡：保留原有“查看合同”“预约记录”等适用入口；无套餐进度数据时不画空进度条。
- “合同签署”和“查看合同”是不同状态：只能由真实合同状态决定标签与目标，不可把所有卡统一写成一个文案。

### 点击映射

| 触发区域 | 唯一结果 | 反馈与返回 |
|---|---|---|
| 套餐名称行或右箭头 | 进入套餐详情页 | 立即按下反馈；返回后保持列表位置 |
| 合同签署 | 进入现有签约路径 | 不改签约结果规则；失败时保留列表状态 |
| 查看合同 | 打开现有合同查看路径 | 返回后保持列表位置 |
| 预约记录 | 打开该咨询师/订单对应的预约记录 | 不跳到无上下文的全局列表，除非原业务已如此定义 |
| 预约下次 | 进入现有预约下次流程 | 不能误触发“进入当前咨询室” |
| 进度条及“剩余 N/总次数” | 纯信息展示 | 不表现为可展开；若现有产品定义可点击，应与套餐名称行同去套餐详情 |

套餐行、快捷入口及卡片其他可点击区域的热区不得重叠；点击箭头不能展开卡片，也不能让合同或预约记录入口失效。

## 3. F-02：删减卡片冗余文字

### 推荐文案替换

| 当前可见文案组合 | 建议保留 | 建议移除/调整 |
|---|---|---|
| “咨询室可进入”＋“距开始 11 分钟·可进入”＋“进入时间：演示规则·提前 15 分钟”＋“进入咨询室” | 状态标签“可进入”；一行“距开始 11 分钟”；按钮“进入咨询室” | 第二次“可进入”和常驻开放规则 |
| “待预约”＋“暂无预约”＋“套餐剩余 8 次，请预约下次咨询”＋“立即预约” | “暂无预约”；套餐区“剩余 8/10 次”；次级按钮“立即预约” | “待预约”和催促句 |
| “审核中”＋大号“预计…完成”＋“目前无需操作”＋通知渠道说明＋“查看进度” | “审核中”；“申请咨询：日期时间”；如可信则一行“预计审核完成：日期时间”；“目前无需操作”可保留 | 未配置通知说明；审核预计时间不要占主标题位置 |

若预约日期是今天，可用“今天 16:07–16:47”帮助快速判断；跨日、跨年显示完整日期。不能只显示相对分钟数而丢失具体预约时间。

### 内容密度验收

- 一张套餐卡在主要信息区最多一个状态标签、一行时间、一行咨询师/方式和一行必要的解释；原有套餐模块不计为“废话”，不得为了缩短卡片而再次隐藏。
- 首卡仍应是列表中最显眼的卡，但不要因重复状态信息把后续卡片过度推到首屏之外。
- 文案缩短后不产生歧义：用户依然能区分咨询开始时间、审核完成预计时间和套餐剩余次数。

## 4. F-03：移除演示与配置语言

### 环境与真实数据规则

- “样例订单·时间与审核规则为演示配置，非真实服务数据”不得出现在真实用户页面。若开发/预览环境必须提示，仅在该环境显示且与正式界面清晰隔离；生产构建必须隐藏。
- “演示规则”“渠道待业务配置”等内部词不可面向用户显示。
- 如果咨询室开放时间由业务配置，使用已确认的真实规则；未获得规则时，不展示“提前 15 分钟”这一数字。可仅展示由当前状态计算出的“可进入/暂不可进入”。
- 如果结果通知渠道未配置，删除整句渠道说明；仅保留可靠信息“可在本页查看进度”。不要暗示会收到某种通知。
- 若页面全部是样例数据，则发布前必须用真实订单数据或明确的测试环境隔离替换，不能只删除提示却继续展示假订单。

### 异常兜底

业务数据缺失时不拼出占位符或内部字段：例如审核预计时间不存在，显示“正在审核”与“查看进度”，而不是“预计 -- 完成”或“渠道待配置”。

## 5. F-04：审核卡主信息恢复申请咨询时段

审核卡的信息顺序固定为：

1. 状态：审核中。
2. **申请咨询：日期＋开始/结束时间**（优先显示，能识别这笔订单）。
3. 咨询师与方式。
4. 审核预期：若有可靠时限，写“预计审核完成：9月17日 15:55 前”；若没有，就写“正在审核，可查看进度”，不编造精确时间。
5. 用户责任：仅在确实无需操作时写“目前无需操作”；如果需要资料，改为相应待办，不与“无需操作”共存。
6. 查看进度入口及原有单次咨询功能入口。

“申请咨询时间”和“预计审核完成时间”必须分别带有清晰前缀，不能只靠字号和颜色区分。审核预计时间发生变化时，应在详情页解释原因；列表只显示最新有效状态，不把旧时间继续当作承诺。

## 6. F-05：弱化待预约按钮，保留清晰可点

- 默认场景：待预约卡的“立即预约”采用原版接近的浅色/描边次级按钮，而不是高饱和全宽实心按钮。位置可回到“暂无预约”同一信息区的右侧，减少卡片高度。
- 紧急性顺序：当前咨询可进入时，“进入咨询室”是全页唯一最高视觉权重动作；“立即预约”和“查看进度”都低一级。
- 即使视觉弱化，按钮仍须具有清楚的边界、文字与足够的触控区域；不可退化成难点的小字链接。
- 不因“没有近期咨询”而自动放大预约按钮，除非产品另行决定；本轮优先保持跨状态视觉一致。

## 7. 页面内操作流与必要反馈

```text
打开“我的咨询室”
  → 扫描第一张卡状态与时间
      ├─ 可进入：点击“进入咨询室” → 现有进入流程
      ├─ 暂无预约：点击次级“立即预约” → 现有预约流程
      └─ 审核中：先看申请咨询时段与预计审核时间 → 可选“查看进度”
  → 需要管理套餐时：看剩余次数与进度条
      ├─ 点套餐名称/右箭头 → 套餐详情页
      └─ 点合同、预约记录或预约下次 → 对应现有路径
```

以下属于交互验收项，而非根据截图判定的现有缺陷：

| 事件 | 最小反馈 | 异常恢复 |
|---|---|---|
| 点击进入咨询室 | `100ms` 内显示按下态；较慢时显示“正在进入…”并防重复点击 | 权限、网络或房间异常时保留预约信息，说明原因并提供重试 |
| 点击立即预约 | 即时按下态；进入既有预约流程 | 预约失败后不丢失已选信息，返回列表时状态不被误改 |
| 点击套餐详情或快捷入口 | 即时按下态和明确导航 | 返回后保留原列表滚动位置 |
| 查看进度 | 进入既有进度详情 | 状态获取失败时显示可理解原因和重试，不把失败误显示为仍在审核 |

不新建“设备检测页”“通知设置页”或额外弹窗，除非代码库已经存在且为完成现有流程所必需。

## 8. 交付与验收清单

### 功能

- [ ] 套餐名/箭头只进入套餐详情页，不展开/收起，也不接管快捷入口点击。
- [ ] 剩余次数、进度条、适用的合同/预约记录/预约下次入口在列表卡内直接可见。
- [ ] 进度条按真实剩余/总次数绘制；缺失或异常数据不显示误导性进度。
- [ ] 审核卡同时区分申请咨询时段与审核预计完成时间。
- [ ] 用户无需进入详情即可说出：下一场咨询何时开始、现在是否能进入、各卡剩余次数与审核中申请的是哪场。

### 文案与层级

- [ ] “可进入”“待预约”“审核中”各只表达一次；不出现同义叠写。
- [ ] 待预约按钮弱于“进入咨询室”，但仍清晰可点击。
- [ ] 用户页面不出现“样例订单”“演示规则”“渠道待业务配置”等内部文案。
- [ ] 未经业务确认的进入开放时间、审核 SLA 和通知渠道不作为确定承诺展示。

### 视觉保护

- [ ] 使用现有组件、颜色和样式变量；不重设计导航、背景、头像、卡片形状或装饰。
- [ ] 修改前后以相同设备宽度截图对比；除本方案列出的内容、入口和必要间距调整外，不出现额外视觉变化。
- [ ] 客服悬浮按钮与底部历史记录入口位置、文字和行为保持不变。
- [ ] 检查窄屏及大字体下文字换行、进度条、快捷入口和按钮是否互相覆盖。

交互原则对应：Norman 的状态可见性/映射/反馈，Tognazzini 的可发现性与用户效率，Nielsen 的识别优于回忆和简洁性；实现以这些目标服务当前任务，不为套用原则引入额外页面或动画。
